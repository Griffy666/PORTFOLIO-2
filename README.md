# RONI / Grifel — Portfolio

A static portfolio site for an AI creative director / visual content designer. Pure HTML, CSS, and a few lines of vanilla JS — no build step, no framework, no dependencies.

## Structure

```
index.html                Homepage — responsive binder spread (mobile portrait + desktop landscape)
work.html                 Portfolio overview (linked from "SEE MORE")
campaigns.html            Category index: Campaigns
fashion.html              Category index: Fashion
products.html             Category index: Products
concepts.html             Category index: Concepts
project-*.html            Individual project case-study pages (one per piece of work — see below)
about.html                 Bio
contact.html               Contact info (email, Instagram, LinkedIn)
404.html                   Not-found page

css/
  reset.css              Base reset
  variables.css          Color + font design tokens (shared everywhere)
  fonts.css              Self-hosted @font-face declarations
  typography.css         Shared type-role classes (masthead, captions, statement, etc.)
  layout.css             Site-wide responsive base + page transition
  home.css               Shared homepage building blocks
  binder-hero.css        Homepage mobile portrait binder layout
  binder-desktop.css     Homepage desktop landscape spread layout
  site.css               Subpage chrome — header, footer, galleries, section headers
  project.css            Case-study page layout — hero, meta, gallery, process, prev/next

assets/
  binder/                Photographed ring-hardware graphics for the homepage binder
  images/                Homepage image crops
  images/gallery/        Category + project-page image crops
  fonts/                 Self-hosted woff2 font files
  source/                Original uploaded photography (uncropped, kept for future re-cropping)

reference/design.png     Original reference photo the homepage was built from
```

### Project case-study pages

Every image in a category gallery (`campaigns.html`, `fashion.html`, `products.html`, `concepts.html`) links to its own `project-<slug>.html` page — an immersive case study with a hero image, client/year/role metadata, a concept paragraph, a flexible gallery that mixes vertical and horizontal crops, an optional process/notes section (used on projects where "the story behind the shot" adds something — e.g. the Campaigns and Concepts work), a final-output frame, and previous/next navigation that cycles through the whole archive in order.

To add a new project: copy the closest existing `project-*.html` as a starting point, swap the title/client/year/role/concept text and image paths, then link to it from the relevant category page and update its neighbors' prev/next links. The template intentionally isn't generated by a build step — it's plain HTML so any file can be hand-edited without tooling.

## Running locally

No build step required. Serve the folder with any static file server, e.g.:

```
python3 -m http.server 8000
```

Then open `http://localhost:8000`.

## Design system

- **Colors / fonts**: defined once in `css/variables.css` and `css/fonts.css`, reused across every page.
- **Homepage** (`index.html`) is a fixed 1068×1472px canvas — a pixel-measured reproduction of the original reference photo. It scales down proportionally on small viewports but never reflows. Its content (text, nav, images) is live HTML; only the acrylic/rail/ring hardware is a baked-in photographic overlay.
- **Subpages** use a normal responsive flow (`css/site.css`) with the same color palette and type roles, so the whole site reads as one system.

## Content placeholders

- **`contact.html`** uses a placeholder email (`hello@roni-grifel.com`) and placeholder Instagram/LinkedIn URLs. Swap them for the real accounts whenever they're available.
- **`project-*.html`** pages use placeholder client names, years, role lines, and concept/process copy, and reuse the category gallery images (there's no separate set of "detail" or "process" shots yet). Replace the text and image paths per project as real case-study material becomes available — see the "Project case-study pages" section above.

## Swapping images

Every image sits in its own `<img>` tag at a fixed container size — replacing the file at the same path keeps the layout intact. Homepage containers are documented in the original build; gallery images live in `assets/images/gallery/` and follow a consistent 4:5 crop ratio (except the Campaigns spread, which uses 3:4).

## Deploying

This is a static site — no build step, no environment variables. It auto-deploys to **GitHub Pages** via `.github/workflows/deploy.yml` on every push to `main` (uses `actions/configure-pages`, which enables Pages on the repo automatically the first time the workflow runs). It can just as easily be dragged into Netlify or Vercel instead if preferred.
